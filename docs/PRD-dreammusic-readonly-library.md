# PRD — DreamMusic 个人音乐库只读同步

> **Status**: ready-for-agent
> **Source**: 当前对话、`docs/CONTEXTS-dreammusic.md` 第 16 节、现有 DreamMusic 代码
> **Issue tracker**: 项目未配置真实 issue tracker，本 PRD 以文件形式发布

## Problem Statement

登录并绑定网易云账号后，DreamMusic 已经可以播放歌曲、展示推荐歌单和“我喜欢”的歌曲，但个人网易云音乐库的同步仍不完整：

- 用户歌单需要通过上游 `user/playlist` 获取；
- 歌单详情和歌曲列表需要统一接入现有播放器；
- 大歌单、多个歌单和大量喜欢歌曲不能被静默截断；
- “我的歌单”和“我喜欢”不应因为其中一个上游接口失败而整体不可用；
- 用户只希望方便读取和同步歌曲数据，不希望 DreamMusic 变成网易云管理后台或社交平台。

## Solution

在现有“登录 → 绑定网易云 → 播放器”的架构内，建立个人音乐库只读闭环：

1. 从网易云读取用户创建和收藏的全部歌单。
2. 从网易云读取“我喜欢”的歌曲 ID，并批量补齐歌曲详情。
3. 读取歌单元数据和歌曲分页数据。
4. 复用现有播放、加入队列、歌曲详情和红心能力。
5. 采用按需读取和 2 分钟内存缓存，不把网易云歌曲数据永久复制到 DreamMusic SQLite。
6. 超过单页限制时分页或分批加载，不静默截断。
7. “我的歌单”和“我喜欢”独立加载、独立显示错误、独立重试。

## User Stories

1. 作为已登录且已绑定网易云的用户，我希望看到自己的网易云歌单，以便从熟悉的音乐库开始播放。
2. 作为用户，我希望看到自己创建的歌单，以便继续使用原有的音乐整理方式。
3. 作为用户，我希望看到自己收藏的歌单，以便同步完整的个人音乐库。
4. 作为用户，我希望歌单卡片展示名称和封面，以便快速识别歌单。
5. 作为用户，我希望点击歌单进入详情，以便浏览其中的歌曲。
6. 作为用户，我希望看到歌单名称和封面，以便确认当前打开的是哪一个歌单。
7. 作为用户，我希望看到歌单中的歌曲列表，以便选择单曲播放。
8. 作为用户，我希望播放整张歌单，以便连续收听。
9. 作为用户，我希望把整张歌单加入当前队列，以便稍后播放且不中断当前歌曲。
10. 作为用户，我希望访问“我喜欢”，以便同步自己标记过的歌曲。
11. 作为用户，我希望“我喜欢”中的歌曲显示歌名、歌手和可用封面，以便确认歌曲身份。
12. 作为用户，我希望从“我喜欢”列表直接播放歌曲，以便快速回到常听内容。
13. 作为用户，我希望从“我喜欢”列表把歌曲加入队列，以便组合新的播放顺序。
14. 作为用户，我希望喜欢歌曲的详情由歌曲 ID 批量补齐，以便列表不会只显示裸 ID。
15. 作为用户，当我的歌单超过单页数量时，我希望可以继续加载下一页，以便不会漏掉歌单。
16. 作为用户，当歌单超过单次歌曲上限时，我希望可以继续加载后续歌曲，以便完整浏览长歌单。
17. 作为用户，当我喜欢的歌曲很多时，我希望系统分批读取详情并显示加载状态，以便知道同步仍在进行。
18. 作为用户，我希望重复打开相同内容时使用短期缓存，以便减少等待和上游请求频率。
19. 作为用户，我希望“我的歌单”加载失败时仍能使用“我喜欢”，以便单个上游故障不影响其它数据。
20. 作为用户，我希望失败区域提供重试操作，以便不需要刷新整个播放器。
21. 作为用户，如果网易云绑定失效，我希望沿用现有 301 流程重新扫码，而不是看到空白页面。
22. 作为用户，我希望未绑定时不能调用个人音乐库接口，以便账户和网易云数据保持隔离。
23. 作为用户，我希望不同 DreamMusic 账户只能看到各自绑定账号的歌单和喜欢歌曲，以便不会泄露个人音乐数据。
24. 作为用户，我希望现有红心按钮继续可用，以便读取同步能力不会破坏既有播放器体验。
25. 作为用户，我希望同步只读取网易云数据，不修改网易云歌单，以便功能边界清晰可控。

## Implementation Decisions

### API 边界

本阶段必需的上游接口：

- `user/playlist`：用户创建和收藏歌单，支持 `uid`、`limit`、`offset`。
- `likelist`：用户喜欢歌曲 ID 列表，使用 `uid`。
- `playlist/detail`：歌单名称、封面、歌曲计数和完整 ID 信息。
- `playlist/track/all`：歌单歌曲详情，支持 `id`、`limit`、`offset`。
- `song/detail`：按逗号分隔的歌曲 ID 批量获取歌曲详情。
- `login/status`：绑定后 UID 缺失时的回退来源。
- 既有 `like`：保留现有播放器红心按钮，但本阶段不新增其它网易云写操作。

中间层继续采用精确白名单、绑定用户解析和自动注入网易云 Cookie。未绑定或绑定失效时，继续使用现有 403/301 行为。

### 同步与缓存

- 只在进入对应视图或打开对应歌单时按需请求。
- 复用 API 客户端现有的 2 分钟内存缓存。
- 不新增 SQLite 歌曲快照、网易云歌单镜像或离线同步表。
- 用户歌单包含创建歌单和收藏歌单。
- 未来需要统一歌曲汇总时，以歌曲 ID 去重；单个列表展示不改变原始歌单顺序。

### 分页与分批

- 用户歌单超过默认页大小时继续请求下一页。
- 歌单歌曲超过单页上限时继续请求后续页。
- “我喜欢”歌曲详情按批量上限分组请求，禁止硬编码静默截断。
- 加载状态应反映当前批次或分页进度；空列表和无更多数据分别表达。

### 错误和降级

- “我的歌单”和“我喜欢”使用独立加载状态。
- 任一数据源失败时，已成功数据继续显示。
- 失败区域提供重试，不要求重新进入 `/dreammusic`。
- 上游 301 触发现有绑定失效流程。
- 403 未绑定、401 DreamMusic 会话失效、502 上游不可达沿用现有错误转换。
- 不把上游原始异常堆栈展示给用户。

### UI 结构

- 复用左栏现有“歌单” tab。
- 歌单入口分为“我的歌单”和“推荐歌单”两个视觉区块。
- “我喜欢”继续复用现有左栏 tab 和歌曲列表。
- 歌单详情复用现有播放全部、加入队列和单曲点击行为。
- 延续现有深空、粉色高亮、半透明圆角和响应式抽屉布局。

### 数据和安全

- 网易云 Cookie 只保存在中间层服务端已有用户存储中。
- 前端只使用 DreamMusic 会话或 API Key，不直接接触网易云 Cookie。
- 所有个人音乐库请求必须绑定到当前 DreamMusic 用户。
- 不新增远程写操作，不新增社交数据表。

## Testing Decisions

### 测试原则

- 只测试外部行为，不测试组件内部实现细节。
- 外部网易云请求使用 fixture/mock，不依赖真实账号、网络或版权。
- 最高优先级是一个完整的个人音乐库读取 seam：从绑定用户进入歌单/喜欢列表，到歌曲能播放或入队。

### 现有 seam 扩展

1. **API 客户端 seam**
   - mock `fetch`，验证路径、参数、分页和批量请求。
   - 覆盖 `userPlaylist`、`playlistDetail`、`playlistTrackAll`、`likedList`、`songDetail`。
   - 覆盖 301、403、502、分页空结果和部分失败。

2. **RTL 组件 seam**
   - mock API fixture，渲染 `PlaylistGrid`、`PlaylistDetail`、`LikedSongsView`。
   - 验证我的歌单和推荐歌单独立显示。
   - 验证歌单分页继续加载。
   - 验证喜欢歌曲分批详情合并。
   - 验证单个区块失败时其它区块仍可操作。
   - 验证播放全部、加入队列和单曲播放。

3. **中间层集成 seam**
   - 使用 stub 上游和真实 Express router。
   - 验证新增白名单接口只对已绑定用户转发。
   - 验证未绑定用户返回 403。
   - 验证 301 会标记绑定失效。

### 回归范围

- 现有 `server/auth`、`server/db`、`server/downloadManager` 测试必须继续通过。
- 现有播放器 reducer、搜索、红心、歌单详情和 DreamMusic 路由测试必须继续通过。
- 每次实现完成后运行类型检查、相关测试和完整测试套件。

## Out of Scope

- 歌单创建、编辑、删除、收藏、取消收藏。
- 评论、动态、关注、粉丝、用户社交关系。
- 云盘歌曲、用户听歌记录、用户等级、收藏计数、用户详情页。
- 专辑/歌手收藏同步。
- 网易云歌曲数据永久落库、离线模式和跨设备云端同步。
- 统一歌曲库的复杂去重、标签、排序和智能分类 UI。
- 修改既有红心按钮行为。
- 新增任何其它网易云写操作。

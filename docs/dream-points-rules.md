# 梦点规则（v0.1）

> 状态：规则草案 + 记账基础设施已实现。扣减场景待用户拍板后启用。

## 已实现

| 类型 | 变动 | 说明 |
|---|---|---|
| `checkin` | +10 / 日 | 东八区自然日，幂等，每天一次 |
| `admin_adjust` | 任意整数 | 管理员在用户管理里调整，必须填原因，写审计日志；**可给自己调整** |
| `song_download` | -1 / 首 | 下载歌曲时扣除；由 `POST /auth/points/download` 统一扣款，余额不足返回 402 |
| `manual` | 预留 | 代码层支持 |

所有变动都写 `dream_point_logs`（delta / balance_after / type / note / ref_id / created_at），
用户中心可查看流水。

## 已确认扣减规则
- **下载歌曲扣 1 梦点**（2026-08-16 用户确认）。
- 扣款发生在服务端成功拿到下载直链之后；余额不足时拒绝下载。
- 前端下载按钮位于播放控制条，音质以下拉框选择，下载使用当前音质。

## 其它扣减规则草案（暂不启用，待确认）

### 方案 A：按播放时长扣点（默认不建议）
- 每累计播放 30 分钟扣 1 梦点。
- 服务端在 `/auth/stats` 上报时按比例扣点。
- 优点：规则简单；缺点：听歌要付费，体验差。

### 方案 B：按「高级动作」扣点
- 每次播放无损 / Hi-Res 音质扣 1 梦点。
- 每次使用私人 FM 扣 1 梦点（或免费）。
- 优点：把梦点定位成「稀有音质/高级功能」的额度。

### 方案 C：按「生成/下载/解锁」扣点
- 下载歌曲：20 梦点/首。
- AI 功能（后续接入时）：按 token 或次数扣点。
- 优点：符合 IvyReverie「梦点」的设定；缺点：依赖未来功能。

## 建议的 MVP
1. 先启用 **方案 B**：`lossless` / `hires` 每次切歌扣 1 点；私人 FM 暂免费。
2. 增加 `type='quality_cost'`，扣到 0 时自动降级到 `exhigh`。
3. 管理员可后台调整（已实现）。
